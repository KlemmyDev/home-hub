# Home Hub

A private, self-hosted family dashboard for a Samsung Galaxy Tab S10 FE+ mounted on the fridge. The tablet is a wall display: portrait (landscape later), always on, glanceable from a metre away, touch-friendly for quick edits.

## What it shows

- Family calendars
- Weekly menu
- Shopping lists
- Widgets for PocketPals (the family's chores and pocket-money app, in `~/PocketPals`)
- Widgets for WattsMyPower (household energy)

## Working agreements

- Stack (decided with the owner): Rust backend (axum + tokio, one small binary), a React UI in `ui/` (TanStack Start in single-page mode: React, TanStack Router and Query, TypeScript, plain CSS in `ui/src/styles.css`), built into `web/` and embedded in the binary; settings in `data/config.json`. The built `web/` is committed, so installing and updating the hub never needs Node: only changing `ui/` does (`bash build-ui.sh`, then `cargo build --release`; dev server: `cd ui && npm run dev`, which proxies `/api` to a hub on 8787). Runs on the owner's own machine as a systemd user service (Linux) or launchd agent (Mac), installed by `install.sh`.
- Updates: the hub's Settings page only *asks* (writes `data/update/request`); a per-minute cron job runs `updater.sh`, which runs `install.sh` (git pull, cargo build, restart) and reports in `data/update/status.json`. Same pattern as PocketPals.
- Widgets are listed in `CATALOG` in `src/main.rs` (PocketPals and WattsMyPower so far); each is a name plus the web address of the app on the home network.
- The owner self-hosts this. Prefer simple, low-maintenance choices (one small service, file or SQLite storage, no external accounts unless needed).
- Design for the tablet first: large type, high contrast, no hover-only interactions, screen stays awake.
- Overview scrolls: nothing on it is cut or squeezed to fit.
- PocketPals integration (`src/pocketpals.rs`): in Settings, PocketPals takes the app's address and an API key made in PocketPals under You, then Developers (`/api/v1`, see PocketPals' `docs/developers.md`). The address is the widget's `url`; the key lives only in `data/config.json` (`pocketpals_key`, `pocketpals_tick`), is never sent to the screen and goes to curl through stdin. Hub API: `POST /api/pocketpals/connect|disconnect`, `GET /api/chores?from&to` (cached 8s), `POST /api/chores/tick` and `/api/chores/step`. The kids' jobs are not in the calendar. Everything chores is in the hub's calm style (Onest, warm page, white cards, each child in their pal's colour): the Home Chores card has a soft tile per child (pal in a ring, what's left, tap to tick, "Show done", how many wait for a grown-up), and the Chores page (`components/Chores.tsx`) has Day (a strip of day tiles with a done bar each, a summary with a ring and each time of day, a card per child with their jobs in the day's order, each tagged with its time of day from PocketPals' `slot`: morning, school, dinner, bed, any) and This week (a grid of children by days, tap a day to open it; what's waiting for a grown-up; days with every job done). Tapping ticks a job at once (a job with steps opens its checklist). The PocketPals and WattsMyPower dock buttons wear each app's favicon. The pals show each child's real pal: PocketPals' jobs API gives every kid a signed `pal_url`, a page on PocketPals that draws just that child's pal (colour, outfit, pet) on a clear background, which the hub shows in a frame (`&head=1` for a round face). Each child's colour is their pal's. The hub must be able to reach PocketPals from the browser, and a hub served over https can't frame a PocketPals served over plain http. Ticks arrive as the child's own, so a grown-up still checks them in PocketPals. Jobs refresh every minute. Kid names and colours come live from PocketPals and are never stored here. A family member with the same name (or first name) as a PocketPals child wears their pal everywhere the hub shows them (`Ava` in `components/Ava.tsx`) and takes the pal's colour (`people` in `hub.tsx`, matched by `palFor` in `lib/pals.ts`).
- WattsMyPower integration (`src/wattsmypower.rs`): in Settings, Apps, WattsMyPower takes the app's address and an API key made in WattsMyPower under Settings, then Developers (`/api/v1`, see WattsMyPower's `docs/developers.md`). Each key is given its own read-only permissions (`live:read`, `history:read`, `costs:read`, `forecast:read`, `insights:read`, `system:read`); the hub learns them when it connects (`wmp_scopes`) and only asks for what the key may read. The key lives only in `data/config.json` (`wmp_key`), is never sent to the screen and goes to curl through stdin. Hub API: `POST /api/wattsmypower/connect|disconnect`, `GET /api/energy/{live|today|history|daily|costs|tariff|savings|forecast|insights}` (cached 10s; answers `{connected, allowed, data|error}`). The Overview's Energy card (when the key may read live power) says in a sentence where the power is coming from, shows WattsMyPower's four tiles (amber solar, home, blue battery with its charge as a bar, grid), today's curve when the key may read history, and made / bought / sold / bill; tapping it opens the Energy page. The Energy page (`components/Energy.tsx`, `/energy`, in the dock when connected) is a page of widgets, each shown only when the key may read it: Right now (the house as a picture with power moving along the lines; four tiles on a phone), Today (a graph of solar, home and battery, midnight to midnight), Battery (ring, when it'll be full, lowest tonight), Cost (today and seven days of bars), Solar forecast, This week (made vs used) and Last 30 days (self-sufficiency). `?demo` shows them all with sample readings; `useEnergy` in `data.ts` is the way for a new widget to read it.
- Overview Today card: a time ribbon (`Ribbon` in `Overview.tsx`), drawn as in the design artifact's Home board: "Today" with "This afternoon, 3pm to 9pm" (always six hours from the start of the current hour, running past midnight in the evening), a row for each family member (and one for each calendar with events that name nobody; a single "Family" row when there's no one), events as soft bars in the person's colour, the time gone hatched behind a red now line, then a yellow "Next up" line and a grey "Tomorrow" line. It's always drawn, events or not. "Open calendar" or a bar open the full Calendar. The header above it is the date, the greeting, today's all-day events as chips, a big Onest clock and the weather.
- Phones: when the screen's short side is under 600px the stage becomes 430 wide (as tall as the screen needs) at about real size, instead of the scaled-down tablet stage. Overview scrolls with the cards in one column, Week becomes a day-by-day list, Month shows dots, Day's hours scroll, and the bottom bar shows icons only. Safe areas (notch, home bar) are read through `#probe`. Tablets keep the fixed stage below.
- The dashboard is a fixed 800 x 1280 portrait stage (the S10 FE+ in portrait, about 800 x 1280 CSS px: an estimate, check `innerWidth` on the tablet) scaled to fit the screen, so landscape just letterboxes for now. Calm light theme (warm off-white `--bg`, white cards with a faint shadow, soft pastel tints of each person's colour, Onest throughout the Home page; designs in the "Family Calendar Variations" design artifact); the app cards are slim white strips with each app's mark, name and whether it answers, shown only for an app added by address alone (one connected with a key has its own widget). No pictures of pals or houses. Fonts load from Google Fonts and fall back to system fonts.
- Calendars come from iCal addresses (Google "Secret address in iCal format", Apple public link, Outlook publish link) pasted into Settings. No accounts or sign-in. `src/calendar.rs` downloads them with `curl` every ten minutes, reads the events (time zones, repeats, skipped dates and moved occurrences included) and answers `GET /api/events?from=&to=` (RFC 3339). The addresses are secrets: they live only in `data/config.json` (git-ignored) and are never sent back to the screen. The Calendar tab has Day (everyone on one timeline), Schedule (a column for each person; tap a name to show only them; the default), Week (seven columns of cards with that night's dinner along the foot) and Month; a phone has Day, Week, Month and List instead (no room for Schedule). Changing view slides the view in from the side it sits on along the tabs, and opening a day from Week, Month or List zooms in (plain CSS keyframes in `morph`, so every browser gets them); the view switch's thumb slides. Day's week strip is a row of white tiles (the chosen day dark, today outlined, a dot for each person who's busy); Schedule has only a slim strip of names over its columns, since the header's faces are the one filter. Every view has the same header: the title with its arrows (and Today when you've moved away), search, the weather and the time; then the view switch, "All" and a round face for each person to show just theirs. The event sheets live in `components/EventSheets.tsx`, drawn as in the design artifact: tapping an event opens its details (when, where, who, repeats, notes; Edit and Delete, and for a repeating one "just this one" or "every time", with Undo); adding or changing one has Which day (with a date picker panel), Starts and Ends steppers with quick lengths, who's going, repeat presets (with a repeat picker panel: every N days / weeks / months / years, the weekdays, an end date) and More details; tapping a gap in Day or Schedule, an empty part of a Week day or a Month date opens a short sheet for that day (what's on, and a quick add with a time and who). Imported calendars only read.
- Family and hub events: `src/family.rs` keeps the family (name + colour) and events made on the hub in `data/family.json` (git-ignored; times are the family's own wall clock, no time zones). Hub events reuse the calendar engine for repeats (daily/weekly with days/monthly/yearly, interval, until a day) and can skip one day. API: `POST /api/people` (replace the list), `GET/POST /api/hub-event`, `POST /api/hub-event/delete` (`only` skips one occurrence). `/api/events` returns them with `hub`, `series`, `people`; people also come in `/api/state`. Editing a repeating event changes all of it; deleting can be just one day.
- Navigation: no top nav. A white bar runs along the bottom (`Bar` in `Stage.tsx`): Home, Calendar, Dinners, a raised + Add in the middle (a new event, on the calendar's day when it's open), Pantry, plus Chores and Energy when those widgets are set up, Travel, and Settings last; the open page sits in a soft lime pill. The Calendar card grows out of the Overview Today card and shrinks back. The calendar header holds a compact clock and date. Designs live in the "Klemm Home Hub" design artifact (boards NavA to NavF, CalFlow, CalDay, CalWeek, CalMonth).
- Only show real data. The calendar and dinner cards show an empty state until they're connected; open the hub with `?demo` to see them filled with sample content. Don't put the family's real names in the repo (it is public); the PocketPals logo is embedded as an inline SVG in `ui/src/lib/icons.tsx`.
- Time format: Settings has a 12-hour / 24-hour choice, saved as `hour24` in `data/config.json` (`POST /api/clock`) and used by the big clock and every event time.
- Dinners (the Menu tab, labelled "Dinners" in the dock): `src/dinners.rs` keeps the family's dinners (a list of names) and a plan by day, with an optional cook, in `data/dinners.json` (git-ignored). API: `GET /api/dinners`, `POST /api/meal` (add or rename), `POST /api/meal/delete` (also clears it from planned days), `POST /api/dinner-plan` (`date` + `meal_id` or a new `name`, optional `cook`; no meal clears the day). The Dinners screen grows out of the Overview's "Dinner tonight" card and, like the Home page, is in the calm style (designs: the Pantry design canvas's P8 "Tonight's dinner" and P9 "After cooking" boards). A switch along the top holds Tonight (the dinner with each ingredient checked against the pantry, a freezer reminder when something needs thawing, what to get with Add to the list, Start cooking, and the next few nights), This week (a row per night; tap a day to pick, type a new one, or say who's cooking; Fill the week and the other tools sit in chips) and Dinner ideas (the list). "Finish" in cooking mode asks "What's left?" for each pantry thing the dinner used (as it was, the recipe's guess, out, or an exact amount), then shows what changed and what went on the shopping list, with Undo. The Overview card shows tonight's dinner. - Pantry (the dock's "Pantry", formerly Shopping; `/shopping` still lands there): `src/pantry.rs` keeps what the family has in `data/pantry.json` (git-ignored): items with an amount and unit, a minimum, a top-up level, a usual shop, whether dinners use it up (`auto`, off for herbs), an optional exact product (barcode) and the list of shops. The Pantry page has three tabs: Shopping list (split by shop, then aisle, with a "shopping at one shop" filter), Stock (levels, +/- buttons, search and filters) and Shops (shops and two switches). Anything that falls below its minimum goes on the shopping list by itself at its usual shop (`Shopping::sync_restock`, after every pantry change; switchable), and comes off again if the stock is put right; ticking an item off adds what was bought to the stock. Cooking: "Finish" in a dinner's cooking mode shows what the dinner used (`planUse` in `lib/pantrylib.ts`, amounts compared with `lib/units.ts`) to check and change, then `POST /api/pantry/use` takes it off, with Undo (or at once, if "Check before using up stock" is off). API: `GET /api/pantry`, `POST /api/pantry/item|item/delete|adjust|use|stores|settings`. Older notes: the Dinners page's simple pantry list moved into this on first start.
- Pantry pictures (`ui/src/lib/pantryicons.tsx`, shapes in `pantryshapes.ts`, tables in `pantrydata1-5.ts`): about 370 flat 48 x 48 SVGs for fruit, veg, meat, dairy, bakery, cupboard staples, drinks, snacks, cleaning, bathroom, baby, pets, lunchbox, Asian and Mexican ingredients and odds and ends. `picFor(name, aisle)` picks one by the item's name (a longer phrase beats a shorter one; no match gives a plain picture for the aisle) and `ItemIcon` draws it on stock rows, shopping rows and the add sheet. To add one: add a row to a `pantrydata` table (id, name, tile colour, comma-separated words that find it, drawing built from the shapes). Dishes keep their own set in `foodicons.tsx`.
- Barcode camera (`ui/src/components/Scanner.tsx`): uses the browser's own `BarcodeDetector` where there is one (Chrome on Android); iPhone and desktop browsers have none, so the same reader (`barcode-detector` with `zxing-wasm`, about 1 MB) loads on first use from the hub's own `assets/` (the server sends `.wasm` as `application/wasm`; nothing comes from a CDN). The camera needs https or localhost. It asks for the plain back camera by name (iPhones can pick the ultra-wide one, which can't focus up close), shows reader errors on the screen instead of hiding them, and has a "Take a photo" button that reads a picture from the phone's own camera app.
- Shopping list: `src/shopping.rs` keeps one list in `data/shopping.json` (git-ignored): items with a name and a ticked flag, in the order added, plus where each is bought (`store`), the pantry item it tops up (`pantry`) with an amount, and a note; adding something already there doesn't duplicate it (a ticked one comes back). API: `GET /api/shopping`, `POST /api/shopping/add|add-many|update|remove|clear` (`clear` takes off the ticked ones). Ideas for later: several lists, matching to Woolworths, Aldi and Coles by barcode.
- Travel (`/travel`, "Travel" in the dock, `components/Travel.tsx`): a map of Australia (pan with a finger, pinch or the +/- buttons to zoom, tap a square) cut into squares, which are the world's map tiles at zoom 10 (`10/x/y`, about 35 km across at Ipswich, 29 to 38 km across Australia; 6,737 of them touch land). Each square can list its top things to see (eight at most) in `lib/travelplaces.ts` (`SQUARES`, each place with an id that never changes, a kind, a line about it and its point; a place must fall inside its square, `cellOf`). Seeing every listed place, or "Mark as done" (any square, listed or not), turns it a soft green; started ones are a fainter green, listed ones a pale amber. Places show as dots once you're close; tapping a dot (or a place's name in a square's list; its circle ticks it straight away) opens the place's own card: its photo (with who took it and the licence underneath), what it is, how far from Ipswich, Mark as seen (with Undo) and Directions (Google Maps). The map, drawn on a canvas in light and darker greys, also has Natural Earth's 1:10m highways (grey lines from afar, white roads close in, the smaller ones only close in), rivers, lakes and dams, and salt lakes. Natural Earth is only accurate to a kilometre or so: there are no streets, and roads can sit a little off at the closest zoom. The land squares, coast, world, roads and water are made by `ui/scripts/travelgrid.mjs <folder of Natural Earth GeoJSON>` into `lib/travelmap.ts` (about 450 KB; don't edit it by hand). So far only six squares around Ipswich have lists (Ipswich, Brisbane, Lockyer Valley, Springfield and Flinders Peak, Minjerribah); "Near home" goes to Ipswich. `src/travel.rs` keeps only what's been ticked, with the day, in `data/travel.json` (git-ignored). API: `GET /api/travel`, `POST /api/travel/seen` and `/api/travel/square` (`id`, `on`, `date`). Photos: each place names a file on Wikimedia Commons in `PHOTOS` (`lib/travelplaces.ts`; free, no account or key, openly licensed); `src/photos.rs` asks Commons for an 800 px copy and its credit through `curl`, keeps it in `data/travel-photos/` and serves it, so the tablet never reaches Wikimedia and each photo is fetched once (`GET /api/travel/photo?file=` answers `{img, credit, licence, page}`, `GET /api/travel/img/{key}.jpg` is the picture; a failed fetch is tried again a day later). A place without a good photo is left out of `PHOTOS` and gets a plain tile in its kind's colour.
- Installable web app: `web/manifest.webmanifest` (display `fullscreen`), `web/sw.js` (network first, falls back to the saved page offline, never stores `/api`) and the logo in `web/icon.svg` plus PNGs in `web/icons/`, all embedded in the binary and served by `src/main.rs`. Browsers only allow service workers on `https://` or `localhost`, so the tablet needs one of those (or Chrome's "Insecure origins treated as secure" flag set to the hub's address).
- Weather: `src/weather.rs` uses Open-Meteo (free, no account or key) through `curl`. Settings searches for a town (`GET /api/weather/search?q=`), then `POST /api/weather/set|units|disconnect`; the place name and coordinates rounded to two decimals live in `data/config.json` (`weather_place|lat|lon|f`). `GET /api/weather` (cached ten minutes) feeds the small weather readout under the clock on the Overview.
- Sheets (modals) must never shift the page. The stage and its panels are `overflow: clip`, so focus or `scrollIntoView` can't scroll them; fields are focused only through `useAutoFocus` / `focusRef` in `ui/src/lib/focus.ts` (after the sheet has risen), never the `autoFocus` attribute or a bare `.focus()`, and `build-ui.sh` stops the build if they appear. A sheet is built hidden first and slides up two frames later (`openSheet` in `hub.tsx`), the viewport meta says `interactive-widget=resizes-visual` and the stage ignores the keyboard's resize while a field is focused, and content that loads after opening must have its space reserved so nothing jumps. Check a new sheet by opening it and watching `layout-shift` entries and `#stage` / `#dash` scroll offsets stay at zero.
- Power saving (`lib/power.ts`, `components/Standby.tsx`, Settings → General → "Screen and battery"; kept per device in `localStorage` as `hub-power`): after a while with no touches the screen shows a dim standby (a clock on black, the next event and weather, drifting a little each minute) and `html.standby` hides the real stage, so nothing is drawn; polling pauses (`focusManager`; the update pulse slows to every 30 seconds), the hourly `useNow` clock stops, and a touch wakes it (that touch does nothing else) and refreshes everything once. It can also stop asking for the screen to stay on (the wake lock), at night hours or after a while, so the tablet's own timer turns the screen off. Cooking mode, the update screen, reminders and the barcode camera hold it awake (`useHold`); a reminder wakes it. A web page cannot set the tablet's brightness.
- Keep secrets (API keys, calendar tokens) in `.env`, never in the repo. Keep `.env.example` current.
- Use plain, calm words in the interface; no jargon.
- Commit small and often. Ask before pushing, creating PRs or changing the repo's settings.

## Commands

- Build: `cargo build --release`; test: `cargo test`; rebuild the UI after editing `ui/`: `bash build-ui.sh`
- Run: `bash start.sh` (reads `.env`, default port 8787)
- Install or update: `bash install.sh` (`--no-service` to only build, `--uninstall` to remove)
