# Home Hub

A private, self-hosted family dashboard for a Samsung Galaxy Tab S10 FE+ mounted on the fridge. The tablet is a wall display: portrait (landscape later), always on, glanceable from a metre away, touch-friendly for quick edits.

## What it shows

- Family calendars
- Weekly menu
- Shopping lists
- Widgets for PocketPals (the family's chores and pocket-money app, in `~/PocketPals`)
- Widgets for WattsMyPower (household energy)

## Working agreements

- Stack (decided with the owner): Rust backend (axum + tokio, one small binary), a React UI in `ui/` (TanStack Start in single-page mode: React, TanStack Router and Query, TypeScript, plain CSS in `ui/src/styles.css`), built into `web/` and embedded in the binary; settings in `data/config.json`. The built `web/` is committed, so installing and updating the hub never needs Node: only changing `ui/` does (`bash build-ui.sh`, then `cargo build --release`; dev server: `cd ui && npm run dev`, which proxies `/api` to a hub on 8787). Runs on the owner's own machine as a systemd user service (Linux) or launchd agent (Mac), installed by `install.sh`.
- Updates: the hub's Settings page only *asks* (writes `data/update/request`); a per-minute cron job runs `updater.sh`, which runs `install.sh` (git pull, cargo build, restart) and reports in `data/update/status.json`. Same pattern as PocketPals.
- Widgets are listed in `CATALOG` in `src/main.rs` (PocketPals and WattsMyPower so far); each is a name plus the web address of the app on the home network.
- The owner self-hosts this. Prefer simple, low-maintenance choices (one small service, file or SQLite storage, no external accounts unless needed).
- Design for the tablet first: large type, high contrast, no hover-only interactions, screen stays awake.
- Overview scrolls: nothing on it is cut or squeezed to fit.
- PocketPals integration (`src/pocketpals.rs`): in Settings, PocketPals takes the app's address and an API key made in PocketPals under You, then Developers (`/api/v1`, see PocketPals' `docs/developers.md`). The address is the widget's `url`; the key lives only in `data/config.json` (`pocketpals_key`, `pocketpals_tick`), is never sent to the screen and goes to curl through stdin. Hub API: `POST /api/pocketpals/connect|disconnect`, `GET /api/chores?from&to` (cached 8s), `POST /api/chores/tick` and `/api/chores/step`. The kids' jobs are not in the calendar. They have their own Chores card on the Overview (under Today) showing only what's left for each child, with a "Show done" toggle for done and waiting ones, and a Chores dock tab (grows out of that card) with a day at a time; tapping ticks a job at once (a job with steps opens its checklist). The PocketPals and WattsMyPower dock buttons wear each app's favicon. The Chores card and page wear the PocketPals look (violet sky, chunky white cards, Figtree) and show each child's real pal: PocketPals' jobs API gives every kid a signed `pal_url`, a page on PocketPals that draws just that child's pal (colour, outfit, pet) on a clear background, which the hub shows in a frame (`&head=1` for a round face). Each child's colour is their pal's. The hub must be able to reach PocketPals from the browser, and a hub served over https can't frame a PocketPals served over plain http. Ticks arrive as the child's own, so a grown-up still checks them in PocketPals. Jobs refresh every minute. Kid names and colours come live from PocketPals and are never stored here.
- Overview Today card: Day (timeline of what's left today) and Week (the seven days side by side with events stacked under each; on a phone they scroll sideways) switch in place; "Open calendar" and tapping a day open the full Calendar (Month is there only).
- Phones: when the screen's short side is under 600px the stage becomes 430 wide (as tall as the screen needs) at about real size, instead of the scaled-down tablet stage. Overview scrolls with the cards in one column, Week becomes a day-by-day list, Month shows dots, Day's hours scroll, and the dock shows icons only. Safe areas (notch, home bar) are read through `#probe`. Tablets keep the fixed stage below.
- The dashboard is a fixed 800 x 1280 portrait stage (the S10 FE+ in portrait, about 800 x 1280 CSS px: an estimate, check `innerWidth` on the tablet) scaled to fit the screen, so landscape just letterboxes for now. Light theme, Comfortaa for the greeting and clock, Onest for everything else; the widget cards are slim strips that borrow each app's own colours (PocketPals violet, WattsMyPower dark) with its mark, name and whether it answers. No pictures of pals or houses. Fonts load from Google Fonts and fall back to system fonts.
- Calendars come from iCal addresses (Google "Secret address in iCal format", Apple public link, Outlook publish link) pasted into Settings. No accounts or sign-in. `src/calendar.rs` downloads them with `curl` every ten minutes, reads the events (time zones, repeats, skipped dates and moved occurrences included) and answers `GET /api/events?from=&to=` (RFC 3339). The addresses are secrets: they live only in `data/config.json` (git-ignored) and are never sent back to the screen. Day, Week and Month views are on the Calendar tab. Imported calendars only read.
- Family and hub events: `src/family.rs` keeps the family (name + colour) and events made on the hub in `data/family.json` (git-ignored; times are the family's own wall clock, no time zones). Hub events reuse the calendar engine for repeats (daily/weekly with days/monthly/yearly, interval, until a day) and can skip one day. API: `POST /api/people` (replace the list), `GET/POST /api/hub-event`, `POST /api/hub-event/delete` (`only` skips one occurrence). `/api/events` returns them with `hub`, `series`, `people`; people also come in `/api/state`. Editing a repeating event changes all of it; deleting can be just one day.
- Navigation: no top nav. A round menu button sits bottom-left; tapping it grows into a floating dock (Overview, Calendar, Menu, Shopping, plus Chores and Energy when those widgets are set up). The Calendar card grows out of the Overview Today card and shrinks back. The calendar header holds a compact clock and date. Designs live in the "Klemm Home Hub" design artifact (boards NavA to NavF, CalFlow, CalDay, CalWeek, CalMonth).
- Only show real data. The calendar and dinner cards show an empty state until they're connected; open the hub with `?demo` to see them filled with sample content. Don't put the family's real names in the repo (it is public); the PocketPals logo is embedded as an inline SVG in `ui/src/lib/icons.tsx`.
- Time format: Settings has a 12-hour / 24-hour choice, saved as `hour24` in `data/config.json` (`POST /api/clock`) and used by the big clock and every event time.
- Dinners (the Menu tab, labelled "Dinners" in the dock): `src/dinners.rs` keeps the family's dinners (a list of names) and a plan by day, with an optional cook, in `data/dinners.json` (git-ignored). API: `GET /api/dinners`, `POST /api/meal` (add or rename), `POST /api/meal/delete` (also clears it from planned days), `POST /api/dinner-plan` (`date` + `meal_id` or a new `name`, optional `cook`; no meal clears the day). The Dinners screen grows out of the Overview's "Dinner tonight" card and shows the week day by day (tap a day to pick, type a new one, or say who's cooking; "Dinner ideas" manages the list). The Overview card shows tonight's dinner. - Shopping list: `src/shopping.rs` keeps one list in `data/shopping.json` (git-ignored): items with a name and a ticked flag, in the order added; adding something already there doesn't duplicate it (a ticked one comes back). API: `GET /api/shopping`, `POST /api/shopping/add|update|remove|clear` (`clear` takes off the ticked ones). The screen grows out of the round menu button and ticks save at once. Ideas for later: categories, several lists, adding the ingredients of a planned dinner.
- Installable web app: `web/manifest.webmanifest` (display `fullscreen`), `web/sw.js` (network first, falls back to the saved page offline, never stores `/api`) and the logo in `web/icon.svg` plus PNGs in `web/icons/`, all embedded in the binary and served by `src/main.rs`. Browsers only allow service workers on `https://` or `localhost`, so the tablet needs one of those (or Chrome's "Insecure origins treated as secure" flag set to the hub's address).
- Keep secrets (API keys, calendar tokens) in `.env`, never in the repo. Keep `.env.example` current.
- Use plain, calm words in the interface; no jargon.
- Commit small and often. Ask before pushing, creating PRs or changing the repo's settings.

## Commands

- Build: `cargo build --release`; test: `cargo test`; rebuild the UI after editing `ui/`: `bash build-ui.sh`
- Run: `bash start.sh` (reads `.env`, default port 8787)
- Install or update: `bash install.sh` (`--no-service` to only build, `--uninstall` to remove)
